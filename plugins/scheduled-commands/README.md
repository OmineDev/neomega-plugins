# 定时命令

原生 Python 插件 `community.scheduled-commands` 0.1.0。按间隔或当地每日多个时间执行服主配置的命令。默认任务列表为空，示例所有任务关闭；安装后由服主授权并启动。独立安装，不依赖其他插件。原创实现，AGPL-3.0-only，不复制 ToolDelta/私有 SDK 源码。

## 配置

参考 `config.example.json`。修改配置后停止并重新启动，生效后才采用新配置。

- `enabled` 控制整个插件，任务自己的 `enabled` 默认 false。停用保留账本；已提交动作不可撤回。
- `schedule.kind=interval`：`seconds` 为 10..31536000 整数，上一轮结束后再计间隔。`run_on_start=true` 仅此模式可用，显式启动时立即执行；故障恢复即使开启此项也会先等待一个间隔。
- `schedule.kind=daily`：设置 1..48 个不同 `HH:MM` 与 IANA 时区（示例 `Asia/Shanghai`）。选择严格晚于启动时刻的时隙；夏令时缺失时刻跳过、重复时刻仅第一次，时钟倒拨不重复已记日期/时刻。延迟超过一分钟的槽位跳过。
- 每任务 1..16 条命令，逐条等明确成功后继续。每条限 4096 UTF-8 bytes，不允许换行/控制字符。不提供脚本、eval、玩家模板或 shell 执行；游戏命令仍具有授权的管理员能力。
- 安装生命周期最多 100 个稳定任务 ID（包括删除墓碑），ID 为小写字母开头的 1..48 位字母/数字/`_`/`-`。删除 ID 后不能重用，不要通过删除账本绕过限制。修改保留 ID 的配置会更换指纹，旧轮不会接着执行。

## 回执与故障恢复

任务和轮次持久化，每条命令有固定 commit ID、意图、截止时间和 operation ID。日志记录任务、轮次、命令序号、结果和 operation ID，不打印命令正文。安装级提交锁和每任务串行循环保证同任务不重叠；不同任务可并行等待操作。

任何 failed / partial / unknown 暂停整个任务，不继续其余命令。重启时中断的轮次也暂停，只查询旧回执，不重放旧命令或补跑离线槽位。即使确认上一条成功，未提交的后续命令也不补执行。原始动作记录持续保留，配置关闭/删除任务后启动仍只读核对回执。

管理员核对旧操作后，将暂停任务 `resume_token` 改成一个新的非空字符串并重新启动，可恢复**未来新轮次**。enabled 开关无法解除暂停；token 不可复用，每任务最多 100 次管理员恢复；恢复不是重新发奖/重放旧轮，旧 unknown 仍保留。每任务最多保留 100 条待核对引用，达到限制暂停新轮；历史 action 记录不删除。运行状态存于安装 storage，日志没有自动重试按钮。

## 兼容与验证边界

面向公开 toolkit/SDK 1.1.0、Host API 1.10、Worker Wire 1.0；ZIP 不含 SDK。只申请 `framework.command.execute`，没有玩家观察、聊天订阅或外部网络权限。离线检查不能证明真实服命令执行；部署时需核验目标 Host、游戏命令权限、时区库及实际回执。
