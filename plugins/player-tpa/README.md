# 玩家互传

安装后保持停止；配置权限并启动后，玩家可以按请求 ID 接受互传。支持 Python 工具包 1.1.0、Host API 1.10。

## 聊天命令

默认前缀 `!tpa`，名字有空格时加英文双引号。

- `!tpa to 玩家名` 请求前往对方；`!tpa here 玩家名` 邀请对方过来。
- `!tpa list [页码]` 查看自己的待处理请求；`!tpa accept ID` 接受、`!tpa deny ID` 拒绝、`!tpa cancel ID` 取消自己发起的请求。
- `!tpa receive on|off` 开关接收；`!tpa block 玩家名` 屏蔽当前在线玩家；`!tpa blocks [页码]` 查看名单；`!tpa unblock UUID` 解除屏蔽（离线也可操作）。屏蔽名单最多100人。
- `!tpa status ID` 查看自己的传送回执。未知或不完整结果须管理员核对，插件不会自动重试。

## 配置

| 配置 | 默认 | 行为 |
|---|---|---|
| enabled | true | 关闭后拒绝新请求；仍可用 status ID 查询本人回执，原回执继续只读核对 |
| aliases | ["tpa"] | 1至8个不含!的小写字母/数字命令，安装间须避免冲突 |
| expiry_seconds | 60 | 请求5至600秒过期，含倒计时 |
| cooldown_seconds | 30 | 成功发起请求后冷却0至3600秒 |
| incoming_limit | 5 | 每人同时待收及待发各1至20个，避免无限队列 |
| warmup_seconds | 0 | 等待0至30秒；启用后双方位移超过0.5格、变维度或失去身份即取消 |
| same_dimension_only | true | 默认拒绝跨维度；关闭后仅使用玩家到玩家传送 |
| max_distance | 0 | 0不限；非零只能与同维度限制一起使用，按采样欧氏距离计算 |
| check_for_blocks | true | SDK传送时检查阻挡方块，不保证落点全面安全 |

停机/重启取消未提交的请求和倒计时，发起冷却重置；接收偏好、屏蔽名单和已提交动作保留。配置由 Host 生命周期重新加载。关闭接收或新增屏蔽会取消对应待处理请求。

名单与请求列表按通知片段分页，每页最多4段正文并附下一页命令。Host明确拒绝提示或传送提交时只终止本次处理；通知提交结果未知时不重投，也不再次确认原事件。提示可能因繁忙或未知回执而未显示，可主动重新查询列表/状态。

## 回执与身份边界

每次传送先将固定动作、提交 ID、双方账户锁和原接受事件 ACK 放进同一持久事务。接受一个请求只创建一个动作；提交响应丢失时仅按原提交查询。pending、unknown、partial 均阻止双方参加新的传送，明确成功或失败后解除。原 ID 的状态查询不会再次提交。尚未确认初始提交的内存锁保留到停止，重启若提交实际成功则从同一持久索引恢复；未提交成功则不会有动作。

聊天必须有与当前观察名单一致的非空 XUID；UUID用于账户键。位置查询须完整且只返回一个实体，实体ID必须与观察结果一致。执行前再核对双方当前名字、XUID、UUID、实体ID和观察epoch。准确名字选择器无法提供执行时UUID原子绑定：目标服若允许短期限内不同账号复用名字，需先解决这一框架限制再启用传送。身份无法核实的聊天仅记录拒绝日志，不猜测收件人。

同时最多处理16个接受请求，繁忙时保留尚未过期请求并提示稍后接受。位置读取失败或超时只取消当前互传。移动取消每秒采样，无法发现采样间移动又返回；查询位置可能为眼高，但仅用于位移/限距判断，最终落点始终交给SDK `teleport_to`。跨维度行为、真实聊天XUID、UUID重连稳定性和游戏客户端结果仍须目标服验收；离线检查不代表这些已经通过。
