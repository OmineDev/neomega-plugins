# 每日签到

`community.daily-signin` 0.1.0 是独立原生 Python 插件。默认按 `Asia/Shanghai` 自然日签到，只记录次数，不发放物品或积分。签到与在线时长插件无依赖。

## 玩家操作

- `!签到` / `!signin`：领取当天签到；重复操作只返回原记录。
- `!签到 状态`：累计次数、当前连签与最长连签。
- `!签到 历史`：本人最近 30 次签到；可配置关闭查询。
- `!签到 待核对`：最多列出 10 条尚未结清的记录。
- `!签到 回执 2026-10-07`：查看指定日期的逐条奖励结果，不会补发。

午夜零点开启新一天，不采用上游的 1440 分钟冷却。中断一天后连签重新从 1 开始。累计/连签按**已受理签到**计数；奖励未知不回退次数。时钟倒拨到最后签到日期之前不会新增资格。无补签、自动签到、随机奖或平台钱包。

## 配置

`config.example.json` 是可直接使用的纯记账默认配置；`config.schema.json` 供配置页面读取。Python SDK 1.1.0 的 schema 子集不支持枚举/数组长度等约束，这些约束由启动校验明确拒绝，不静默忽略。

| 配置 | 默认与规则 |
| --- | --- |
| `enabled` | `true`；关闭后停止新签到，保留状态/历史/回执查询和后台原操作对账 |
| `timezone` | `Asia/Shanghai`；首次初始化后固定，更换需要另行数据迁移 |
| `aliases` | `['!签到', '!signin']`；1–8 个互不重复、无空格的 `!` 开头命令，长度最多32字符 |
| `rewards.enabled` / `rewards.base` | `false` / `[]`；开启后必须有基础奖励；关闭会同时关闭所有新里程碑奖励 |
| `consecutive.enabled` / `cumulative.enabled` | 均 `false`，`rules=[]`；每类最多32条 |
| `announcement.enabled` | `false`；新签到受理时向全服公告一次，不等价于奖励成功 |
| `history.enabled` | `true`；关闭不删除防重记录 |

奖励对象的 `kind` 为 `item`、`scoreboard` 或 `command`。每次签到基础奖励→连续里程碑→累计里程碑→公告，最多16个动作。每种奖励只使用对应字段，其他字段保留 schema 默认值。

- `item`：`item` 为物品ID，`count` 1..32767，`data` 默认为0。
- `scoreboard`：`objective` 为已有计分板名称（1..16 个 ASCII 字母、数字、`_ . -`），`amount` 为1..2147483647。插件不创建计分板，不替服主决定额度。
- `command`：管理员提供单行命令，最多4096 UTF-8字节；仅支持 `{player}`，替换成经过 SDK 编码的准确玩家选择器。字面花括号写作 `{{` 和 `}}`，不支持其他格式化表达式，不替换聊天内容。此能力使用广泛命令权限，配置管理员须可信。

配置启动时，使用公开 SDK 按最大合法玩家名（命令256 UTF-8字节；计分板holder依SDK限制128字节）展开模板，按SDK及Host的JSON编码上界（含Go对 `< > & U+2028 U+2029` 的转义）计算同次可能触发的基础、连续和累计奖励在账本意图与提交动作中的两份完整 JSON 大小。该合计不得超过192 KiB；其余64 KiB留给事件、账户历史、分页索引、公告与事务元数据。按整组而非单条展开长度计量，单条命令按最大合法玩家名展开后也必须满足Host原有的32 KiB上限。重复占位符和JSON转义均计入；超预算配置明确拒绝，不截断或删减奖励。64 KiB是为最多100个键的索引页、30条历史、身份、session、事件三元组、cause及固定结构预留的预算，不是对任意长度Host元数据或任意大计数的无条件保证。受理前还用 SDK `Transaction.prepare()` 加Host编码大小检查实际完整256 KiB边界，超限会明确提示未受理、资格未消耗；首笔仍保持账本、全部动作与ACK原子提交。

里程碑规则形状：`{"rule_id":"week-one","count":7,"rewards":[...]}`；服主填写实际奖励。`rule_id` 为1..48个小写字母、数字、`_ -`，两类间唯一，首次配置后永久绑定种类、次数与奖励内容；删除不会移除绑定，修改规则须使用新 ID。连续奖在每段连签到第 N 天时各一次，断签后可再次达成；累计奖在终身次数恰好到 N 时一次。启用、修改或新增规则均不追溯补奖。

## 安装与权限

需要 Host API 1.10、Worker Wire 1.0、公开 Python SDK 1.1.0，Python ≥3.10。市场安装保持停止；检查配置，授予所列权限，再启动。

申请 `players:list` 用于当前观察身份校验，订阅持久 `chat.received`；`framework.command.execute` 用于反馈、物品/管理员命令奖励与可选公告；`framework.scoreboard.add` 用于可选积分奖励。存储由原生安装隔离 API 提供，无外部服务、Host bearer、私有数据库或跨插件数据访问。

聊天必须带可靠非空 XUID，并与当前观察名单中的 UUID、XUID、姓名唯一一致。观察失效时拒绝请求；不使用旧姓名账迁移或姓名兜底。奖励准备前再次校验身份，固定10秒截止时间。准确名称不是执行时 UUID 原子绑定：目标服仍须验证账号 UUID 稳定、聊天 XUID 可用，并保证短窗口内不同账号不能复用同名。

## 回执与数据

首次事务同时保存账户进度、当天记录、事件防重摘要、全部固定动作意图、原 commit ID 和聊天 ACK。后续仅按原 commit/operation ID 查回；重启、重投、跨日或配置关闭均不会重建旧奖励。明确失败不自动补发，`partial` / `unknown` 长期保留供人工核对；不要通过改账号/业务日期/数据库绕过未知结果。

明确的在途操作配额拒绝会以无奖励事务保存该事件的未受理标记，次数和当日资格不变；旧事件重投仍保持拒绝，需要玩家重新发送命令。回复通知遇同类配额拒绝仅记日志，不改变账本或自动重放；其它系统错误仍上报。

完整原始操作回执以每条签到独立的内容寻址分片保存（每片最多32 KiB原始JSON字节，base64编码），账本只保存原operation ID、状态和完整证据引用。逐片事务及哈希核验保证不会截断证据；先登记分片版本，再逐片写入，全部完成后才发布引用。中断可重入，旧版内联回执仍可读取。终结记录清理时先归档账本，再按持久游标逐片清除所有版本（包括中断产生的未引用片）；分页项保留到清理结束，重启继续。未知/部分完成的账本及证据不清理。

账户摘要及规则墓碑永久保留；详细终结回执满90天后由分页后台扫描清理，实际清理时间随页数延后；未知/部分完成记录不清理。每页最多100个记录键；最近30次历史只保存日期与次数摘要。历史奖励详情清理后无法查询，旧事件仍有精简防重摘要。账本只证明受理与原始操作回执，不把计数成功当作游戏资产到账。
